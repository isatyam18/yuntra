# Good first issues

After publishing the repository, create a `good first issue` label in GitHub and apply it to small, isolated work such as:

- Improve a PowerShell error message or installation note.
- Add a test for a documented Windows edge case.
- Add a reproducible context-retrieval fixture.
- Clarify a manual adapter handoff.
- Improve documentation or example-project coverage.

Do not label architecture rewrites, schema changes, policy changes, or unverified automated integrations as good first issues.
